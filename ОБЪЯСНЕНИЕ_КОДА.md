## 1. Что делает программа

AeroPaint — это программа для рисования, где вместо мышки используется
**геймпад, который вы держите как баллончик с краской**.

В геймпаде спрятаны два датчика, как в смартфоне:

- **гироскоп** — чувствует, *как быстро вы поворачиваете* геймпад;
- **акселерометр** — чувствует *ускорение*, в том числе постоянную силу
  тяжести (то есть «где низ»), и резкие рывки руки.

Программа делает из этого следующее:

| Что вы делаете с геймпадом | Что происходит на экране |
|---|---|
| Поворачиваете в сторону / наклоняете вверх-вниз | Двигается прицел (точка, куда «брызгает» краска) |
| Нажимаете правый курок | Идёт краска; чем сильнее нажали, тем гуще |
| Трясёте геймпад вперёд-назад | «Взбалтываете» баллончик: растёт индикатор перемешивания |
| Не взболтали баллончик | Краска бледная и рваная (но без капель) |
| Нажимаете кнопки (A, B, X, Y, LB, RB…) | Палитра, отмена, повтор, калибровка, размер сопла |
| Ничего не нажимаете и не двигаете геймпад 3 секунды | Прицел плавно возвращается в центр экрана; стоит пошевелить геймпад — возврат останавливается |

Если геймпада нет, всё то же самое работает **от мыши**: движение мыши
заменяет поворот геймпада, а быстрое «потряхивание» мышью взбалтывает краску.

## 2. Азбука программирования: минимум, чтобы читать код

Программа написана на языке **Python**. Это текст, который компьютер
выполняет сверху вниз, строка за строкой. Ниже — всё, что встречается в коде.

### 2.1. Переменная

Переменная — это «коробочка с именем», в которой лежит значение.

```python
nozzle = 38.0          # в коробочку nozzle положили число 38.0
nozzle = nozzle + 4.0  # теперь там 42.0
```

Знак `=` значит не «равно», а «положить в коробочку».

### 2.2. Типы значений

| Тип | Пример | Что это |
|---|---|---|
| `int` | `5`, `-3` | целое число |
| `float` | `0.5`, `38.0` | число с дробью |
| `str` | `"привет"` | строка текста |
| `bool` | `True`, `False` | «да» / «нет» |
| `None` | `None` | «ничего, пусто» |
| `list` | `[1, 2, 3]` | список — упорядоченный набор |
| `tuple` | `(10, 20)` | кортеж — как список, но менять нельзя (используется для точек и цветов) |
| `dict` | `{"a": 1, "b": 2}` | словарь — «слово → значение» |

Цвет в программе — это три числа от 0 до 1: красный, зелёный, синий
(RGB). Например `(0.91, 0.16, 0.18)` — красный.

### 2.3. Условия и циклы

```python
if mix < 0.3:        # если перемешивание меньше 0.3...
    print("тряси!")  # ...выполнить это (отступ — часть языка!)
else:
    print("ок")

for i in range(3):   # повторить 3 раза: i = 0, затем 1, затем 2
    print(i)

while self.running:  # повторять, пока running равно True
    ...
```

**Отступы (пробелы в начале строки) в Python — это не красота, а смысл.**
Всё, что сдвинуто вправо под `if`/`for`/`def`, принадлежит этому блоку.

### 2.4. Функция

Функция — это именованный кусок кода, который можно вызвать много раз.

```python
def change_nozzle(delta):      # def = "определить функцию"
    nozzle = nozzle + delta    # то, что делает функция
    return nozzle              # return = "вернуть результат"

change_nozzle(4.0)             # вызов функции
```

В скобках после имени — **параметры** (входные данные). `->` и слова после
двоеточия в скобках (например `dt: float`) — это подсказки о типах; на
работу программы они не влияют, это комментарии для человека.

### 2.5. Класс, объект, self

**Класс** — чертёж. **Объект** — вещь, сделанная по чертежу. У объекта есть
свои данные и свои функции (они называются **методами**).

```python
class SprayCan:                 # чертёж "баллончик"
    def __init__(self):         # вызывается при создании объекта
        self.mix = 0.0          # у каждого баллончика своя перемешанность

    def shake(self):
        self.mix = self.mix + 0.085

can = SprayCan()                # создали объект
can.shake()                     # вызвали его метод
print(can.mix)                  # 0.085
```

`self` — это «сам этот объект». `self.mix` — «поле mix именно у меня».
Метод `__init__` — **конструктор**, он готовит объект к жизни.
Если имя начинается с `_` (например `self._time`), это сигнал «внутренняя
деталь, снаружи не трогать» (запретом не является, это договорённость).

### 2.5.1. Наследование

```python
class MouseBackend(InputBackend):   # MouseBackend "наследует" InputBackend
```

Это значит: «MouseBackend — это особый вид InputBackend, у него есть всё,
что есть у InputBackend, плюс свои дополнения». Так сделано, чтобы мышь и
геймпад выглядели для остальной программы одинаково.

### 2.6. Модуль, импорт, пакет

Один `.py`-файл — это **модуль**. Папка с файлом `__init__.py` — **пакет**.
Чтобы использовать код из другого файла, его **импортируют**:

```python
import math                          # встроенная библиотека математики
from .config import AppConfig        # из соседнего файла config.py взять AppConfig
```

Точка перед именем (`.config`) значит «в той же папке, что и я».
`..` — на уровень выше.

### 2.7. Библиотеки, которые использует проект

| Библиотека | Зачем |
|---|---|
| `pygame-ce` | окно, рисование на экране, клавиатура, мышь, геймпад, звук |
| `numpy` | быстрые расчёты над большими таблицами чисел (весь холст — это таблица) |
| `Pillow` (в коде `PIL`) | сохранение картинки в PNG/JPG |
| `ctypes` | вызывать функции из «чужих» библиотек (нужно для датчиков геймпада) |
| `math`, `random`, `time`, `os`, `json`, `zlib`, `glob`, `sys`, `datetime`, `colorsys`, `dataclasses`, `threading` | встроенные в Python инструменты: математика, случайные числа, время, файлы, JSON, сжатие, цвета |

Они перечислены в файле `requirements.txt`; команда
`py -m pip install -r requirements.txt` их устанавливает.

### 2.8. Ещё несколько приёмов, которые вы увидите

- **f-строка**: `f"Хват: {deg} градусов"` — вместо `{deg}` подставится значение.
- **Комментарий**: всё после `#` компьютер игнорирует — это заметки людям.
- **Докстринг**: текст в тройных кавычках `"""..."""` в начале файла/функции —
  описание того, что это.
- **Распаковка**: `x, y = point` — достать из пары `(10, 20)` числа в две
  переменные.
- **try / except**: «попробуй это; если случится ошибка — сделай вот это вместо
  падения программы».
- **lambda**: маленькая безымянная функция в одну строку.
- **Срез списка**: `a[2:5]` — элементы с 2-го по 4-й.
- **Словарь-как-меню**: в `app.py` клавишам сопоставлены функции (см. 8.4).
- **`@property`**: метод, который вызывается без скобок и выглядит как поле
  (`can.needs_shaking`, а не `can.needs_shaking()`).
- **`@dataclass`**: короткая запись класса, который в основном хранит данные.
- **`from __future__ import annotations`**: техническая строка вверху файлов;
  позволяет писать подсказки типов в современном виде. На логику не влияет.

### Зачем разделение на файлы

Один огромный файл читать невозможно. Поэтому код поделён **по
обязанностям** — как отделы в компании:

| Файл | «Отдел» | Ответственность |
|---|---|---|
| `inputs/*` | Приёмная | Узнать, что делает геймпад (или мышь) |
| `orientation.py` | Штурман | Понять, куда направлен геймпад |
| `shake.py` | Технолог | Понять, достаточно ли взболтана краска |
| `spray.py` | Художник | Нанести краску на холст |
| `canvas.py` | Архив | Хранить картинку, отмену, сохранять |
| `ui.py` | Оформитель | Нарисовать индикаторы и подсказки |
| `audio.py` | Звукорежиссёр | Шипение и стук |
| `config.py` | Пульт настроек | Все «ручки» в одном месте |
| `app.py` | Директор | Каждый кадр вызывает остальных в нужном порядке |

Отделы не лезут в дела друг друга. Например `spray.py` ничего не знает про
геймпад: он просто получает «нарисуй от точки A до точки B». Благодаря этому
код можно проверять по частям и менять одну часть, не ломая остальные.

### Служебные файлы, которых вы можете увидеть

- `__pycache__/` и файлы `.pyc` — Python создаёт их сам для ускорения запуска.
  Трогать не нужно; в GitHub они не попадают (запрещены файлом `.gitignore`).
- `output/autosave.aept` — автосохранение раз в 2 минуты.
- `output/aeropaint_ДАТА_ВРЕМЯ.png` и `.aept` — сохранения по клавише `S`.
  PNG — обычная картинка; `.aept` — формат проекта AeroPaint (см. 8.1).
- `.gitignore` — список того, что git (система учёта версий) игнорирует.

## 4. Путь данных за один кадр: главная схема

Программа работает как мультфильм. Примерно **120 раз в секунду**
(`target_fps = 120`) повторяется один и тот же **кадр**. За кадр:

```
        ГЕЙМПАД (или мышь)
              │  gyro, accel, trigger, buttons          ← inputs/*.poll()
              ▼
   ┌──────────────────────────┐
   │ 1. Нажатия кнопок        │  handle_actions: палитра, отмена, ...
   │ 2. Поворот хвата         │  apply_grip → rotate_grip
   │ 3. Встряхивание          │  gravity → axis_accel → SprayCan.update_motion
   │ 4. Ориентация            │  OrientationFilter.update → clamp → canvas_point
   │ 5. Рисование             │  SprayGun.paint (если курок нажат)
   │ 6. Возврат в центр       │  update_auto_center
   │ 7. Расслоение краски     │  SprayCan.update_settling
   │ 8. Обновление картинки   │  _blit_region
   │ 9. Отрисовка экрана      │  draw → ui.py → pygame.display.flip()
   └──────────────────────────┘
```

Ключевое число — **dt** (дельта-тайм): сколько секунд прошло с прошлого кадра
(около 0.008 с). Почти все расчёты умножаются на `dt`. Пример: если вы
поворачиваете геймпад со скоростью 2 радиана в секунду, то за кадр угол
вырастет на `2 × 0.008`. Так движение не зависит от того, быстрый у вас
компьютер или медленный.

## 5. Разбор файлов: запуск и настройки

### 5.1. `run.py` — точка входа

Это единственный файл, который вы запускаете (`py run.py`). Он ничего не
рисует — только готовит параметры и включает программу.

**Построчно:**

1. `import argparse, sys` — подключает инструменты: `argparse` читает
   параметры, которые вы пишете после `run.py` (например `--backend mouse`),
   `sys` нужен, чтобы завершить программу с кодом ошибки.
2. `def main() -> int:` — главная функция. Возвращает число: `0` — всё
   хорошо, `1` — была ошибка.
3. `parser = argparse.ArgumentParser(...)` и вызовы `parser.add_argument(...)`
   объявляют, какие параметры бывают:
   - `--backend sdl|mouse` — принудительный выбор источника;
   - `--size 1920x1080` — размер холста;
   - `--debug` — показать отладочную панель сразу;
   - `--sensitivity 700` — сколько пикселей на радиан поворота (чувствительность);
   - `--grip 0|90|180|270` — поворот хвата.
4. `args = parser.parse_args()` — прочитать то, что вы ввели.
5. `try: import pygame ... except ImportError:` — проверка, что pygame
   установлен. Если нет — сообщение и выход.
6. `cfg = AppConfig()` — создать набор настроек по умолчанию (см. `config.py`).
7. Применить ваши параметры: `--size` режется по букве `x` на ширину и
   высоту; `--sensitivity`, `--grip`, `--debug` записываются в настройки.
8. `AeroPaint(cfg, backend_name=args.backend).run()` — создать программу
   и запустить её главный цикл. Здесь программа «живёт» до закрытия окна.
9. Последние строки `if __name__ == "__main__": sys.exit(main())` значат:
   «если файл запустили напрямую (а не импортировали) — вызвать `main()`».

### 5.2. `aeropaint/config.py` — пульт настроек

Тут нет логики, только числа. Каждый `@dataclass` — группа настроек.
Любое число отсюда можно менять и сразу пробовать. Единицы: ускорение
в м/с², угловая скорость в рад/с, угол в радианах (π радиан = 180°),
время в секундах.

#### `OrientationConfig` — про направление геймпада

| Параметр | Значение | Что делает |
|---|---|---|
| `accel_tau` | 1.0 | За сколько секунд «наклон» подтягивается к направлению силы тяжести, когда геймпад неподвижен |
| `accel_still_rate` | 0.12 | Если геймпад вращается медленнее этого (рад/с), он считается неподвижным |
| `gyro_deadzone` | 0.010 | Гироскоп всегда чуть «шумит». Показания меньше этого значения считаются нулём, иначе прицел бы медленно плыл |
| `px_per_rad` | 700.0 | **Чувствительность**: сколько пикселей на 1 радиан поворота. Больше — прицел быстрее бегает по экрану |
| `grip_rotation` | 90.0 | Как геймпад повёрнут в руке (0/90/180/270°). Меняется клавишей `G` |
| `auto_center_delay` | 3.0 | Через сколько секунд бездействия начать возврат в центр |
| `auto_center_delay_offscreen` | 10.0 | То же, но если прицел упёрся в край экрана |
| `auto_center_ramp` | 1.0 | За сколько секунд возврат разгоняется до полной силы (плавный старт) |
| `auto_center_tau` | 0.5 | Скорость сближения с центром: меньше — быстрее; 0 — возврат выключен |
| `auto_center_min_rate` | 0.05 | Минимальная скорость, чтобы точка дошла до самого центра, а не замедлялась бесконечно |
| `calibration_samples` | 180 | Сколько замеров гироскопа усредняется при калибровке |
| `calibration_tolerance` | 0.35 | Если во время калибровки замеры «гуляют» сильнее — значит, геймпад двигали, калибровка отклоняется |

#### `ShakeConfig` — про встряхивание

| Параметр | Значение | Что делает |
|---|---|---|
| `accel_threshold` | 6.0 | Какое ускорение считается «взмахом» (иначе обычные движения руки засчитывались бы) |
| `min_stroke_interval` | 0.07 | Два взмаха чаще, чем за 0.07 с, — это дребезг, второй не считается |
| `max_stroke_interval` | 0.80 | Пауза дольше 0.8 с обрывает серию взмахов |
| `mix_per_stroke` | 0.085 | Сколько «перемешанности» даёт один взмах (≈12 взмахов до полной) |
| `idle_decay` | 1/240 | Краска расслаивается сама: полная перемешанность улетучивается примерно за 4 минуты |
| `spray_decay` | 0.018 | Дополнительно перемешанность тратится, пока вы брызгаете |
| `good_mix` | 0.75 | Выше этого — краска ложится идеально |
| `warn_mix` | 0.30 | Ниже — красная подсказка «ВСТРЯХНИТЕ» и рваная подача |
| `clog_mix` | 0.12 | Ниже — баллончик «засорился», почти не красит, только плюётся |
| `rumble_ms` | 55 | Длительность вибрации геймпада на каждый взмах (миллисекунды) |

#### `SprayConfig` — про сопло и краску

| Параметр | Что делает |
|---|---|
| `base_radius` 38 | Радиус пятна в пикселях по умолчанию |
| `min_radius` 6, `max_radius` 170 | Пределы размера сопла |
| `hardness` 0.45 | 0 — размытое облако, 1 — почти резкий край |
| `flow` 1.0 | Общая «подача» краски (множитель густоты) |
| `spacing_ratio` 0.12 | Расстояние между «отпечатками» вдоль линии, в долях радиуса. Меньше — плавнее, но тяжелее для компьютера |
| `distance_gain` 0.9 | Насколько отдаление баллончика от холста увеличивает пятно |
| `alpha_per_stamp` 0.055 | Прозрачность одного отпечатка (маленькое число, поэтому краска набирается слоями) |

#### `CanvasConfig`

Размер холста `1600×900`, цвет фона `(0.96, 0.95, 0.92)` (тёплый белый),
`undo_depth = 24` (сколько шагов отмены помним), `autosave_interval = 120`
(секунд между автосохранениями).

#### `AppConfig`

Сводит всё вместе: внутри лежат `orientation`, `shake`, `spray`, `canvas`,
плюс `target_fps = 120` (желаемое число кадров в секунду) и `debug_overlay`
(показывать ли отладочную панель). Слово `field(default_factory=...)` —
технический приём, чтобы у каждого набора настроек были свои копии
вложенных групп.

#### `DEFAULT_PALETTE`

Восемь цветов для клавиш 1–8: чёрный, красный, оранжевый, жёлтый, зелёный,
синий, фиолетовый, белый.

## 6. Разбор файлов: источники ввода (папка `inputs`)

Идея папки: **приложение не должно знать, откуда берутся данные**. Есть
несколько «поставщиков» (геймпад, мышь), и все они выдают одинаковую
«сводку» — объект `SprayState`. Остальной код работает только со сводкой.

### 6.1. `inputs/base.py` — общий шаблон

**`SprayState`** — сводка о состоянии на данный момент:

| Поле | Что внутри |
|---|---|
| `connected` | подключён ли источник |
| `gyro` | три числа: скорость вращения вокруг осей X, Y, Z (рад/с) |
| `accel` | три числа: ускорение по осям X, Y, Z (м/с²) |
| `trigger` | насколько нажат курок, от 0 до 1 |
| `buttons` | словарь «действие → нажата ли», например `{"undo": True, "palette": False}` |
| `battery` | текст о заряде |
| `rate_hz` | сколько раз в секунду приходят данные |
| `note` | пояснение для нижней строки |

Метод `pressed("undo")` отвечает, нажато ли это действие.

**`RateMeter`** — счётчик частоты. Каждый вызов `tick()` добавляет единицу;
раз в полсекунды он делит накопленное на прошедшее время и запоминает.
Нужен только для отладочной панели («частота отчётов, Гц»).

**`InputBackend`** — «пустой шаблон» источника. Описывает, что должен уметь
любой источник:

- `start()` — подготовиться, вернуть `True`/`False` (получилось или нет);
- `poll(dt)` — опросить и вернуть `SprayState`;
- `rumble(strength, ms)` — завибрировать (по умолчанию ничего не делает);
- `close()` — освободить ресурсы;
- поле `applies_grip` — применять ли «поворот хвата» (мыши он не нужен).

**`EdgeTracker`** — «детектор нажатия». Проблема: кнопка, зажатая на
полсекунды, для программы — это ~60 кадров «нажато». А нам нужно, чтобы
«Отмена» сработала **один раз**. `just_pressed(state, "undo")` возвращает
`True` только в тот кадр, когда кнопка **перешла** из «не нажата» в
«нажата». Он помнит прошлое состояние в словаре `_previous`.

### 6.2. `inputs/sdl_sensor.py` — настоящий геймпад

Самый технический файл. **SDL** — это библиотека, на которой работает
pygame, и она умеет читать гироскоп геймпада. pygame эти функции сам не
показывает, поэтому код обращается к SDL напрямую через `ctypes`.

Константы:
- `SENSOR_ACCEL = 1`, `SENSOR_GYRO = 2` — номера датчиков в SDL;
- `TRIGGER_AXIS = 5` — номер оси правого курка;
- `BUTTON_MAP` — какая кнопка геймпада какое действие запускает:

| Действие | Кнопка |
|---|---|
| `palette` | A (номер 0) |
| `undo` | B (1) |
| `redo` | X (2) |
| `calibrate` | Y (3) |
| `debug` | Back/View (4) |
| `save` | Start/Menu (6) |
| `size_down` | LB (9) |
| `size_up` | RB (10) |

- `POWER` — перевод состояния батареи на русский.

**`find_sdl2()`** — ищет файл библиотеки SDL2 (`SDL2.dll` на Windows) рядом
с установленным pygame; если не нашла — спрашивает у системы. Возвращает
загруженную библиотеку или `None`.

**Класс `SdlSensorBackend`:**

- `__init__` — заводит пустые «коробочки» и два буфера по 3 числа для
  гироскопа и акселерометра (SDL будет писать туда значения).
- `_bind(sdl)` — **«объясняет» ctypes типы функций SDL**: «эта функция
  принимает целое число и возвращает указатель» и т. д. Без этого вызовы
  бы не работали. Если в SDL нет нужных функций (версия старше 2.0.14), будет
  ошибка `AttributeError`, и `start()` сообщит «версия SDL2 старше…».
- `start()` — по шагам: убедиться, что геймпад вообще виден → открыть его →
  найти SDL2 → привязать функции → проверить, что SDL считает устройство
  геймпадом → открыть → убедиться, что у него **есть** гироскоп и
  акселерометр → включить оба датчика. На любом шаге при неудаче записывает
  причину в `self.note` и возвращает `False`.
- `poll(dt)` — главный метод, вызывается каждый кадр:
  1. читает гироскоп и акселерометр в буферы;
  2. читает курок: SDL даёт от −1 (отпущен) до 1 (нажат), формула
     `(значение + 1) × 0.5` переводит в 0…1;
  3. читает кнопки по `BUTTON_MAP`;
  4. добавляет искусственную «кнопку» `spray` = курок нажат больше чем на 6%;
  5. читает состояние батареи;
  6. возвращает всё в `SprayState`.
- `rumble()` — вибрация (внутри `try`, чтобы отсутствие мотора не ломало программу).
- `close()` — закрывает геймпад.

### 6.3. `inputs/mouse.py` — запасной вариант

Мышь притворяется геймпадом, чтобы вся остальная программа работала без
изменений.

- `poll()` берёт, на сколько пикселей сдвинулась мышь за кадр (`dx`, `dy`),
  и **превращает сдвиг в «скорость вращения»**: делит на `px_per_rad` и на
  `dt`. Получается то же, что выдал бы гироскоп.
  Вертикаль: `dy` положительный, когда мышь едет вниз, поэтому «вращение по X»
  = `dy / ...` — и прицел идёт вниз, как и должно.
- **Встряхивание мышью.** Программа считает «скорость со знаком» (вправо
  — плюс, влево — минус), смотрит, как она **изменилась**, и выдаёт это как
  «ускорение по продольной оси». Быстрое потряхивание вправо-влево даёт
  скачки со сменой знака — детектор встряхивания принимает их за взмахи.
  `ACCEL_SCALE = 1.4e-4` подобран так, чтобы энергичное потряхивание давало
  около 15 м/с² при пороге 6.
- Ускорение по Y всегда `G + a_long`: «сила тяжести 9.8 + то, что насчитали».
- Левая кнопка мыши → курок = 1.
- `applies_grip = False` — поворот хвата мыши не нужен.

### 6.4. `inputs/factory.py` — выбор источника

Функция `create_backend(preferred, px_per_rad)`:

1. Строит список попыток: если вы просили `mouse` — только мышь; иначе
   сначала `sdl` (геймпад), потом `mouse`.
2. Для каждого создаёт объект и вызывает `start()`. Если успех — печатает
   «Источник ввода: …» и возвращает его.
3. Если неудача — запоминает причину и пробует следующего.
4. Если не вышло вообще ничего — ошибка (на практике мышь работает всегда).

Возвращает пару: «выбранный источник» и «список попыток» (список — для
диагностики; в приложении он не используется).

## 7. Разбор файлов: мозг программы

### 7.1. `orientation.py` — «куда направлен геймпад»

Задача: превратить поток чисел гироскопа в точку на холсте.

#### Идея интегрирования

Гироскоп говорит не «геймпад повёрнут на 30°», а «вращается со скоростью
0.5 рад/с». Чтобы получить угол, скорость **накапливают** по времени:

```
угол = угол + скорость × dt
```

Это и называется интегрированием. Минус: крошечные ошибки накапливаются
(**дрейф**) — прицел медленно уползает. Против дрейфа есть три средства:
калибровка, подтяжка по силе тяжести и возврат в центр.

#### `_wrap(angle)`

Приводит угол к диапазону от −π до π (от −180° до 180°). Угол 190°
превратится в −170°. Нужно, чтобы углы не росли бесконечно.

#### `rotate_grip(vec, degrees)`

**Поворот хвата.** Геймпад можно держать как обычный, а можно как баллончик
(повёрнутым на бок). Тогда «вправо» для датчиков — это уже другая ось. Эта
функция поворачивает вектор показаний на заданный угол вокруг оси Z.
Формулы: `x' = x·cos + y·sin`, `y' = −x·sin + y·cos`, где `cos`/`sin` —
косинус и синус угла. Применяется **один раз** сразу после чтения датчиков,
после чего остальной код вообще не знает про хват.

#### `Pose`

Три числа: `yaw` (рыскание — поворот вокруг вертикали, это «влево-вправо»),
`pitch` (тангаж — «вверх-вниз»), `roll` (крен). Это текущее положение.

#### `CalibrationError`

Собственный вид ошибки: «геймпад двигали при калибровке».

#### `OrientationFilter` — главный класс

Поля:
- `pose` — текущие углы;
- `zero` — углы, которые считаются «центром холста»;
- `bias` — «собственный дрейф» гироскопа: даже на столе он показывает
  не ровно ноль; калибровка это измеряет и затем вычитает;
- `_samples` — пока `None`, калибровки нет; если список — идёт набор замеров.

**Калибровка.**
- `begin_calibration()` — начать собирать замеры (`_samples = []`).
- `calibrating` — «идёт ли калибровка?» (свойство).
- `calibration_progress` — доля готовности от 0 до 1 (для надписи «Калибровка 40 %»).
- `_finish_calibration()` — когда набралось 180 замеров: считает **среднее**
  по каждой оси, смотрит **разброс** (самое большое отклонение от среднего).
  Если разброс больше `calibration_tolerance`, значит, геймпад двигали —
  бросает `CalibrationError`. Иначе запоминает среднее как `bias` и
  объявляет текущее положение центром (`recenter`).
- `recenter()` — «считать текущее направление центром холста»: записывает
  текущие углы в `zero`. Клавиша `R`.
- `rate` — текущая угловая скорость поворота геймпада (рад/с), её каждый
  кадр пересчитывает `update`. Приложение смотрит на неё, чтобы понять,
  двигаете вы геймпад или он лежит неподвижно (нужно для возврата в центр).

**`update(gyro, accel, dt)` — главный расчёт, каждый кадр.**

1. Если идёт калибровка — просто собирает замеры и выходит.
2. Вычитает `bias` из показаний гироскопа; всё, что меньше `gyro_deadzone`
   (шум), обнуляет.
3. Интегрирует: `pitch += gx·dt`, `yaw += gy·dt`, `roll += gz·dt`.
4. **Подтяжка по силе тяжести.** Акселерометр в покое показывает вектор
   силы тяжести (≈9.8 м/с², «вниз»). Зная это, можно проверить и поправить
   наклон. Но нельзя делать это всегда: во время движения акселерометр
   показывает не только тяжесть, и коррекция стягивала бы прицел обратно.
   Поэтому она включается **только** если:
   - длина вектора ускорения близка к 9.8 (между 8.4 и 11.2), и
   - геймпад почти не вращается (`rate < accel_still_rate`).
   Тогда углы `pitch` и `roll` чуть-чуть смешиваются с углами, вычисленными
   из акселерометра (через арктангенс `atan2`). Доля смешивания `a`
   зависит от `dt` и `accel_tau`, но не больше 0.25.
   **Рыскание (yaw) по акселерометру исправить нельзя** — тяжесть не
   зависит от поворота вокруг вертикали (нужен был бы компас). Поэтому
   горизонтальный дрейф лечится возвратом в центр.

**`clamp_to_canvas(width, height)` — «стена».**
Прицел нельзя уводить за экран. Метод ограничивает угол пределами холста:
максимальный угол по горизонтали = `(ширина/2) / px_per_rad`, по вертикали
аналогично. Важно, что ограничивается **сам угол**, а не картинка. Поэтому
при развороте обратно прицел реагирует мгновенно, а не «отматывает» лишнее.
Возвращает `True`, если прицел сейчас упирается в стену (по любой из осей) —
по этому признаку краска не идёт, прицел краснеет, и включается задержка
10 с вместо 3.

**`auto_center(dt, strength)` — плавный возврат в центр.**
Для каждой оси (yaw и pitch):
1. `delta` — на сколько прицел отошёл от центра.
2. `follow = 1 − e^(−dt/tau)` — доля пути, которую нужно пройти за кадр
   (экспоненциальное сближение). Следствие: **далеко от центра — быстро,
   близко — медленно**, прицел мягко тормозит у цели.
3. `step = max(|delta|·follow, floor) · strength` — шаг: либо доля пути,
   либо минимальная скорость (чтобы точка дошла до центра, а не
   приближалась вечно), умноженное на `strength` (0…1 — «сила»).
4. Если шаг больше, чем осталось — встать ровно в центр; иначе сдвинуться на
   `step` в сторону центра.

**`canvas_point(width, height)` — в пиксели.**
`x = ширина/2 + (yaw − zero.yaw) · px_per_rad`,
`y = высота/2 + (pitch − zero.pitch) · px_per_rad`.
То есть центр экрана плюс отклонение в радианах, умноженное на
чувствительность. (В пикселях ось Y идёт **вниз**: 0 — верх экрана.
Именно здесь стоит «плюс» — направление вертикали, которое вы просили
поменять.)

#### `DistanceEstimator` — «насколько баллончик далеко от стены»

Реальное «приближение/отдаление» мы узнаём только по ускорению вперёд-назад
по продольной оси. Двойное интегрирование: ускорение → скорость → расстояние.
Это даёт быструю ошибку, поэтому:
- скорость каждый кадр гасится (`× 0.90`);
- если вы не двигаетесь вперёд-назад больше 2 секунд (`hold_time`), значение
  плавно возвращается к нулю;
- значение ограничено между −0.85 и 1.6.
Это не измерение, а «художественный эффект»: дальше → шире и бледнее пятно.
`reset()` обнуляет всё.

### 7.2. `shake.py` — встряхивание и качество краски

Файл не зависит от pygame и numpy — это чистая логика.

#### `PaintQuality`

Описание «как сейчас красит баллончик»:
`density` (густота), `saturation` (насыщенность цвета), `sputter`
(глубина провалов подачи), `clogged` (засорился). Свойство `is_clean` — «краска идеальна».

#### `ShakeDetector` — считает взмахи

Как отличить встряхивание от обычного движения? Взмах = **резкое ускорение,
после которого направление сменилось**. Метод `update(accel, dt)` каждый
кадр делает:

1. Накапливает внутренние часы `_time`, считает, сколько прошло с прошлого
   взмаха (`since`).
2. Если прошло дольше `max_stroke_interval` — серия закончилась,
   запомненное направление забыто.
3. Если ускорение упало ниже 40% порога — «взвести» детектор (`_armed`).
   Нужно, чтобы постоянная тяга в одну сторону (например, вы просто
   поднесли баллончик к холсту) не считалась взмахами.
4. Если ускорение меньше порога — выйти (взмаха нет).
5. Узнать знак (вперёд `+1` или назад `−1`). Взмах **не** засчитывается,
   если: направление то же, что у прошлого; слишком быстро после прошлого
   (дребезг); детектор не взведён.
6. Иначе взмах засчитан: запоминаем направление и время, увеличиваем
   `total_strokes`, возвращаем `1`.

#### `SprayCan` — состояние баллончика

- `mix` — уровень перемешанности от 0 до 1.
- `update_motion(accel, dt)` — скармливает ускорение детектору; за каждый
  взмах поднимает `mix` на `mix_per_stroke` (но не выше 1).
- `update_settling(dt, spraying)` — краска расслаивается: `mix` падает на
  `idle_decay·dt`, а пока вы брызгаете — ещё и на `spray_decay·dt`.
- `needs_shaking` — `True`, если `mix < warn_mix` (0.30).
- `strokes_to_good` — сколько взмахов осталось до `good_mix`
  (подсказка «взмахов: N» на экране).
- `quality()` — переводит `mix` в `PaintQuality`:
  - `mix ≥ 0.75` → идеальная краска (всё по единице);
  - иначе `t` — «степень недомешанности» (0 — почти хорошо, 1 — совсем плохо):
    густота падает до 38%, насыщенность — до 55%;
  - при `mix < 0.30` появляется «рваная подача»;
  - при `mix < 0.12` баллончик засорён: густота ×0.25.

#### `gravity_free_axis_accel(accel, gravity)`

Из показаний акселерометра надо убрать постоянную силу тяжести — останется
ускорение от вашей руки. Берёт `lin = accel − gravity`, смотрит компонент по
оси Y (продольная ось баллончика). Если же движение идёт больше по другим
осям (вы трясёте боком), берёт полную длину вектора со знаком Y-компонента,
чтобы взмахи не терялись.

#### `GravityEstimator`

Оценка направления силы тяжести: **скользящее среднее**. Каждый кадр новое
значение чуть-чуть (4%) подмешивается к накопленному. Быстрые рывки руки
«сглаживаются», остаётся постоянная составляющая — тяжесть. При первом
вызове просто запоминает первое показание.

### 7.3. `spray.py` — как рисуется краска

Работает с **numpy-таблицей** `canvas`: это массив формы
`(высота, ширина, 3)` — для каждого пикселя три числа RGB от 0 до 1.

#### Что такое «отпечаток» (stamp)

Краска не рисуется сплошной линией. Вместо этого вдоль пути много раз
ставится **мягкое круглое пятно** (отпечаток), и они накладываются друг
на друга, как слои аэрозоля. Прозрачность одного отпечатка очень мала
(`alpha_per_stamp = 0.055`), поэтому краска **копится слоями**: чем дольше
держите курок — тем гуще.

#### `spray_kernel(radius, hardness, variant)` — «форма пятна»

Возвращает квадратную таблицу чисел от 0 до 1 — густоту в каждой точке
пятна: 1 в центре, плавно к 0 на краю. Профиль — **гауссиана** (колокол)
`exp(−d²/(2σ²))`, где `d` — расстояние от центра в долях радиуса, а `σ`
зависит от `hardness`. Затем профиль подправляется так, чтобы на самом краю
был ровно 0 (иначе была бы видна «кайма» круга).
Если `variant ≥ 0` — пятно умножается на «зернистый шум» (функция `_grain`):
часть капель «не долетает» — получается фактура аэрозоля.
Готовые формы запоминаются в `_KERNEL_CACHE`, чтобы не считать заново.
(`GRAIN_VARIANTS = 8` — всего 8 вариантов зерна на каждый размер.)

#### `stamp(canvas, x, y, kernel, color, alpha)` — поставить один отпечаток

1. Определяет, в каком прямоугольнике холста окажется пятно.
2. Если пятно частично за краем холста — обрезает (иначе ошибка).
3. **Альфа-смешивание:** для каждого пикселя
   `новый = старый·(1 − a) + цвет·a`, где `a = форма·alpha`. Код делает это
   сразу для всей области: `region *= 1 − a; region += цвет·a`.

#### `SprayGun`

- `rng` — генератор случайных чисел (для зерна).
- `mark_dirty / take_dirty` — «грязный прямоугольник». Чтобы не
  перерисовывать весь холст 1600×900 каждый кадр, запоминается минимальный
  прямоугольник, где что-то изменилось; приложение обновляет на экране
  только его.
- `radius_for(nozzle, distance)` — итоговый радиус: сопло, увеличенное
  удалением, но в пределах `min_radius…max_radius`.
- `paint(canvas, p0, p1, nozzle, distance, color, trigger, quality, dt)` —
  главный метод. Что происходит:
  1. Если курок не нажат — выйти.
  2. **Цвет** при плохой перемешанности смешивается с серым (бледнеет).
  3. **Прозрачность отпечатка** = `alpha_per_stamp · flow · trigger ·
     густота / (1 + 0.85·удаление)`: сильнее нажали — гуще; дальше — реже.
  4. Если есть `sputter` (рваная подача) — прозрачность умножается на
     волну синуса со случайной добавкой (подача «пульсирует»).
  5. **Шаги вдоль линии.** От точки `p0` до `p1` ставится столько
     отпечатков, сколько нужно по расстоянию (шаг = `radius·spacing_ratio`,
     минимум 1 пиксель), но не больше 256 за раз (защита от «зависания»
     при очень резком движении).
  6. В каждой точке: случайный вариант зерна → отпечаток.
  7. Запоминает «грязный прямоугольник» с запасом.

## 8. Разбор файлов: холст, звук, экран, главный цикл

### 8.1. `canvas.py` — картинка и её хранение

- `pixels` — та самая таблица `(высота, ширина, 3)` чисел от 0 до 1.
  **Это и есть рисунок.**
- `clear()` — залить фоном; очистить историю отмены.
- `to_uint8()` — перевести числа 0…1 в целые 0…255 (так хранят цвета
  в картинках).
- **Отмена и повтор.** Перед началом каждого мазка (`begin_stroke`)
  делается **снимок** всей картинки, сжатый `zlib` (пустой холст сжимается
  в килобайты). Снимки лежат в списках `_undo` и `_redo`. `undo` кладёт
  текущее состояние в `_redo`, а из `_undo` достаёт и восстанавливает
  прежнее; `redo` — наоборот. Это общий метод `_step`. Хранятся не более
  `undo_depth` (24) снимков; новый мазок очищает `_redo`.
- `export_image(path)` — сохранить в PNG/JPG через Pillow.
- `save_project(path, meta)` — собственный формат `.aept`: первые 4 байта
  — метка `AEPT`, потом длина заголовка, потом сам заголовок в JSON
  (размер, время, пометки), потом сжатые пиксели.
- `load_project(path)` — обратное чтение (в приложении кнопки загрузки
  нет, зато тесты проверяют, что сохранённое читается без потерь).
- `maybe_autosave(directory)` — вызывается каждый кадр; если с прошлого
  сохранения прошло ≥ 120 секунд — пишет `output/autosave.aept`. Сначала
  во временный файл, затем переименование: так при внезапном выключении не
  останется «полуфайла».

### 8.2. `audio.py` — звук без звуковых файлов

Все звуки **вычисляются при запуске**.

- `_hiss()` — шипение. Берётся секунда **белого шума** (случайные числа),
  затем пропускается через простейший фильтр
  `acc = acc·0.7 + шум·0.3` (убирает «песок», оставляя «ш-ш-ш»), края
  плавно затухают на 0.02 с, чтобы зацикленный звук не щёлкал.
- `_rattle()` — стук шарика: короткая (0.055 с) синусоида 220 Гц плюс
  щелчок шума, затухающая по экспоненте.
- `_to_sound()` — перевод чисел в звук pygame (стерео, 16 бит).
- `CanAudio`:
  - `start()` — запускает звуковую систему; при любой ошибке `enabled =
    False`, и программа просто работает без звука;
  - `spray(intensity)` — пока курок нажат — крутит шипение по кругу,
    громкость от `0.15` до `0.75` в зависимости от нажатия; отпустили —
    останавливает;
  - `rattle()` — проиграть стук (на каждый взмах);
  - `stop()` — выключить всё при выходе.

### 8.3. `ui.py` — всё, что рисуется поверх холста

- Цвета интерфейса: `INK`, `PAPER`, `PANEL`, `ACCENT` (жёлтый), `ALARM`
  (красный), `GOOD` (зелёный), `GREY`, `DIM`.
- `load_font` — **шрифт**: стандартный шрифт pygame не знает кириллицу,
  поэтому перебираются системные (`arial`, `segoeui` и т. д.), берётся
  первый найденный.
- `Fonts` — четыре размера шрифта.
- `to255` — цвет из 0…1 в 0…255.
- `panel` — полупрозрачная тёмная подложка под текстом.
- `Hud`:
  - `notify_shake()` — вспышка при взмахе (баллончик на экране дрожит,
    шарик внутри мечется); `update(dt)` — гасит вспышку и крутит «пульс»;
  - `_text` — вспомогательная функция: текст по центру;
  - `draw_can` — рисует баллончик слева: корпус, **уровень перемешанности**
    (зелёный/красный столбик), колпачок цвета краски, шарик, надпись
    «NN % перемешано» и «взмахов: N»;
  - `draw_shake_prompt` — большая мигающая надпись «ВСТРЯХНИТЕ БАЛЛОНЧИК»;
  - `draw_crosshair` — прицел: кружок размером с пятно; красный, если упёрся
    в край;
  - `draw_status` — нижняя полоса: источник, батарея, сопло, цвет, перемешано,
    сообщения;
  - `draw_palette` — окошко палитры: 8 ячеек, три полоски (тон,
    насыщенность, яркость);
  - `draw_debug` — отладочная панель справа (клавиша `F1`).

**HSV**: способ задавать цвет тремя числами — тон (оттенок), насыщенность,
яркость. Для редактирования палитры он удобнее RGB; `colorsys` переводит
туда-обратно.

### 8.4. `app.py` — главный цикл (директор)

#### Создание (`__init__`)

1. `pygame.init()` — включить pygame, `set_mode` — открыть окно размером с холст.
2. Создаются все «отделы»: `Canvas`, `Hud`, `SprayGun`, `SprayCan`,
   `OrientationFilter`, `GravityEstimator`, `DistanceEstimator`, `EdgeTracker`.
3. `create_backend(...)` — выбирает геймпад или мышь.
4. `CanAudio().start()` — звук.
5. Начальные значения: палитра, цвет №1, размер сопла, флаги.
6. `idle_time` — сколько секунд вы ничего не трогаете.
7. `_max_jump_sq` — квадрат «разрешённого прыжка» (см. ниже).
8. В режиме мыши курсор Windows скрывается и «запирается» в окне
   (`set_grab`), чтобы мышь не уходила за пределы.
9. Показывается подсказка внизу.

#### Мелкие помощники

- `notify(text, seconds)` — показать сообщение внизу на N секунд.
- `_blit_region(x0, y0, x1, y1)` — **перенос картинки из numpy в pygame.**
  Два «мира» хранят картинку по-разному: numpy — `[строка, столбец]`,
  pygame — `[x, y]`. Код берёт нужный кусок, переводит в 0…255 и
  транспонирует. Обрабатывает только указанный прямоугольник.
- `refresh_canvas()` — обновить весь холст целиком (после отмены и т. п.).
- `set_color`, `select_palette`, `apply_hsv`, `change_nozzle` — смена цвета,
  ячейки, правка оттенка, размер сопла (в пределах min…max).
- `calibrate`, `save_png`, `undo`, `redo`, `new_canvas`, `recenter`,
  `cycle_grip` — действия. `_history` — общая часть undo/redo: выполнить
  и, если получилось, перерисовать и показать сообщение.
  `cycle_grip` крутит хват 0→90→180→270, при этом **сбрасывает центр**,
  удаление и оценку силы тяжести, потому что система координат поменялась.

#### События и ввод

- `handle_events()` — просит у pygame все накопившиеся события: закрытие
  окна и нажатия клавиш.
- `handle_key(event)` — **словарь «клавиша → действие»**:
  `C` калибровка, `R` центр, `Z` отмена, `Y` повтор, `S` сохранить, `G` хват,
  `N` новый холст, `P` палитра, `F1` отладка, `[` и `]` размер сопла,
  `Esc` выход, `1…8` — ячейка палитры. Любая клавиша ещё и ставит
  `_key_activity = True` («я что-то делаю» — для таймера бездействия).
- `handle_actions(state)` — кнопки геймпада через `EdgeTracker`
  (срабатывают один раз): калибровка, отмена, повтор, сохранение, отладка,
  палитра. LB/RB: в палитре листают ячейки (по одному нажатию), вне палитры
  меняют размер сопла, **пока зажаты**.
- `handle_palette_sticks()` — когда палитра открыта, левый стик меняет тон
  (влево-вправо) и насыщенность (вверх-вниз), правый — яркость. Значения
  внутри «мёртвой зоны» 0.18 игнорируются (стики никогда не стоят точно в
  нуле). Если что-то изменилось — `_sticks_active = True`.

#### `step(dt)` — один кадр, самое важное

В порядке выполнения:

1. `state = self.backend.poll(dt)` — спросить геймпад.
2. Обработать кнопки и стики.
3. `apply_grip` — повернуть показания на угол хвата (кроме мыши).
4. **Взмахи.** Убрать тяжесть → `axis_accel` → `update_motion`. Если взмах:
   дрожь баллончика на экране, стук, вибрация геймпада. Если именно этим
   взмахом `mix` пересёк 0.75 — сообщение «Краска перемешана».
5. **Ориентация.** `filter.update(...)` (с обработкой ошибки
   калибровки), `clamp_to_canvas` (стена), `distance.update`,
   `canvas_point` → итоговая точка `point`.
6. **Рисование.**
   - курок = 0, если открыта палитра или идёт калибровка;
   - `spraying = trigger > 0.06`;
   - только что нажали → `begin_stroke()` (снимок для отмены) и запоминаем
     стартовую точку;
   - отпустили → забываем старую точку;
   - **защита от разрыва**: если точка «прыгнула» дальше, чем на полдиагонали
     за один кадр, линию не проводим, начинаем с новой точки;
   - если нажат курок и прицел не у стены — `gun.paint(...)`.
7. `update_auto_center` — возврат в центр (см. ниже).
8. Расслоение краски.
9. Обновить на экране изменившийся прямоугольник.
10. Автосохранение.
11. `draw(...)` — нарисовать кадр.

#### `update_auto_center` — **плавное центрирование (новое)**

1. **Таймер бездействия.** Считается активностью: курок нажат, открыта
   палитра, идёт калибровка, **любая** кнопка геймпада нажата, нажата
   клавиша, шевелятся стики в палитре, **или вы двигаете геймпад**
   (угловая скорость `filter.rate` больше порога `accel_still_rate`,
   0,12 рад/с — это медленный поворот примерно на 7° в секунду).
   Если что-то из этого есть — `idle_time = 0`. Иначе `idle_time` растёт
   на `dt`. Лёгкое дрожание неподвижно лежащего геймпада ниже порога и
   возврату не мешает.
2. **Выбор задержки.** `delay = 10 с`, если прицел упёрся в край экрана
   (`at_limit`), иначе `3 с`.
3. Когда `idle_time ≥ delay`:
   `t = (idle_time − delay) / auto_center_ramp`, ограниченное числом 0…1;
   сила = `t²·(3 − 2t)` — это **smoothstep**, «плавная S-образная кривая»:
   сила разгоняется от 0 к 1 за 1 секунду без рывка.
   Эта сила передаётся в `filter.auto_center(dt, сила)`.

Результат: ничего не трогаете 3 секунды → прицел начинает мягко ползти к
центру, на секунду разгоняется, а у цели плавно тормозит. Нажали кнопку или
**просто повели геймпадом** — возврат тут же выключается и отсчёт
начинается заново. Дошёл до центра — тоже прекращается сам.

*Историческая заметка:* раньше движение геймпада активностью не считалось,
поэтому после первых 3 секунд возврат работал постоянно и тянул прицел в
центр даже во время ведения без курка. Теперь это исправлено.

#### Отрисовка

- `draw()` — по порядку: холст, прицел (скрыт при открытой палитре),
  баллончик, подсказка «встряхните», надпись калибровки, палитра, отладка,
  нижняя строка, и `pygame.display.flip()` — показать всё на экране
  (двойная буферизация: сначала рисуем «за кулисами», потом показываем).
- `status_lines()` — набор цветных надписей для нижней полосы.
- `debug_rows()` — строки отладочной панели: частота, хват, FPS, значения
  датчиков, углы, смещение нуля, точка, удаление, перемешивание,
  количество взмахов.

#### `run()` — «двигатель»

```python
while self.running:
    dt = ... clock.tick(120) / 1000      # ждём, пока пройдёт кадр, получаем dt
    self.hud.update(dt)
    self.handle_events()
    self.step(dt)
```
`min(..., 0.05)` ограничивает `dt` на случай, если компьютер «подвис», чтобы
физика не сошла с ума. После выхода из цикла — выключить звук, закрыть
геймпад, `pygame.quit()`.

```
py -m tests.test_core
py -m tests.test_app_headless
py -m tests.render_demo
```

|---|---|
| `test_core.py` | Логику по частям: взмахи, качество краски, калибровку, поворот хвата, «стену», возврат в центр, оценку удаления, рисование, холст/отмену/сохранение. Печатает `OK` или `FAIL` для каждой проверки |
| `test_app_headless.py` | Всё приложение целиком, но **без реального окна** — на «картонном» pygame (`stub_pygame.py`). Имитирует кадры, встряхивание, рисование, клавиши, сохранение |
| `stub_pygame.py` | Подделка pygame: те же названия, но вместо экрана — пустышки. Нужна только тестам |
| `render_demo.py` | Не проверяет, а **рисует** наглядные картинки в `demo/`: `01_mix_levels.png` (краска при разной перемешанности), `02_distance.png` (пятно на разных расстояниях), `04_session.png` (расход перемешанности) |

| Прицел двигался быстрее/медленнее | `config.py` → `px_per_rad` (больше — быстрее) |
| Возврат в центр начинался позже/раньше | `config.py` → `auto_center_delay` (3 с) и `auto_center_delay_offscreen` (10 с) |
| Возврат был быстрее/мягче | `config.py` → `auto_center_tau` (меньше — быстрее), `auto_center_ramp` (дольше — плавнее старт) |
| Выключить возврат в центр | `auto_center_tau = 0` |
| Поменять вверх/вниз | `orientation.py` → `canvas_point`: заменить `height * 0.5 + dy` на `height * 0.5 - dy`; для мыши ещё поменять знак `dy` в `inputs/mouse.py` |
| Взмахи не засчитываются | `config.py` → `accel_threshold` (уменьшить) |
| Взмахи засчитываются от обычных движений | `accel_threshold` (увеличить) |
| Меньше взмахов до готовности | `mix_per_stroke` (увеличить) |
| Краска расслаивалась медленнее | `idle_decay`, `spray_decay` (уменьшить) |
| Краска гуще/прозрачнее | `alpha_per_stamp` (больше — гуще) |
| Края мягче/резче | `hardness` |
| Размер сопла по умолчанию | `base_radius` |
| Пределы размера сопла | `min_radius`, `max_radius` |
| Размер холста | запуск `py run.py --size 1920x1080` или `CanvasConfig` |
| Цвета палитры | `config.py` → `DEFAULT_PALETTE` |
| Назначение кнопок геймпада | `inputs/sdl_sensor.py` → `BUTTON_MAP` |
| Назначение клавиш | `app.py` → словарь `actions` в `handle_key` |
| Хват | клавиша `G` или `--grip 90` |
| Интервал автосохранения | `CanvasConfig.autosave_interval` |
| Громкость шипения | `audio.py` → `set_volume(min(1.0, 0.15 + 0.6 * intensity))` |
| Надписи интерфейса | `ui.py` и `app.py` (тексты в кавычках) |

**Совет:** меняйте по одному числу и сразу запускайте. Если стало хуже —
верните прежнее значение. Перед правкой сделайте копию файла.

## 11. Словарь терминов

| Термин | Простыми словами |
|---|---|
| **Альфа / прозрачность** | Насколько просвечивает нижний слой. 0 — невидимо, 1 — полностью закрашено |
| **Акселерометр** | Датчик ускорения; в покое показывает силу тяжести |
| **Бэкенд (backend)** | «Поставщик данных»: геймпад или мышь |
| **Гироскоп** | Датчик скорости вращения |
| **Гауссиана** | Колоколообразная кривая; даёт мягкое пятно |
| **dt** | Время одного кадра в секундах |
| **Дрейф** | Накопление мелких ошибок: прицел медленно уползает |
| **Интегрирование** | Накопление: «скорость × время = расстояние» |
| **Калибровка** | Измерение собственного «шума» датчика в покое, чтобы потом вычитать |
| **Кадр (frame)** | Один «снимок» программы, повторяется ~120 раз в секунду |
| **Класс / объект** | Чертёж / вещь по чертежу |
| **Контроллер / геймпад** | Устройство с кнопками и датчиками |
| **Кэш** | Запомненный готовый результат, чтобы не считать заново |
| **Мёртвая зона** | Диапазон около нуля, где показания игнорируются |
| **Модуль / пакет** | Файл `.py` / папка с `__init__.py` |
| **numpy-массив** | Таблица чисел, с которой можно считать целиком, а не по одному элементу |
| **Отпечаток (stamp)** | Одно мягкое пятно краски |
| **Парсинг** | Разбор текста на части |
| **Пиксель** | Одна точка на экране |
| **Радиан** | Единица угла: π рад = 180° |
| **RGB / HSV** | Два способа задавать цвет |
| **Свойство (`@property`)** | Метод, вызываемый без скобок |
| **SDL** | Библиотека для окон, ввода и звука; под капотом pygame |
| **Тангаж / рыскание / крен** | Наклон вверх-вниз / поворот влево-вправо / вращение вокруг оси |
| **Триггер / курок** | Аналоговая кнопка, которая возвращает значение от 0 до 1 |
| **Исключение** | Ошибка во время работы; ловится `try/except` |
| **Хват** | Как геймпад повёрнут в руке |
| **Smoothstep** | Кривая `t²(3−2t)` для плавного разгона |
| **Headless** | «Без головы»: без окна и экрана |
| **Коммит** | Сохранённая версия проекта в git |
