# AeroPaint

Растровый редактор, в котором рисуют не мышью, а геймпадом, удерживаемым
как аэрозольный баллончик. Направление устройства задаёт точку нанесения,
аналоговый курок работает клапаном, а перед работой баллончик надо
взболтать — иначе краска ложится бледно, неровно и плюётся каплями.

Проект сделан под Flydigi Apex 5, но привязки к конкретной модели в коде нет.

## Установка

```
pip install -r requirements.txt
```

## Порядок запуска

Сначала диагностика: она покажет, каким способом на вашей машине доступны
гироскоп и акселерометр, и запишет результат в `mapping.json`.

```
python probe_gamepad.py
```

Затем само приложение:

```
python run.py
```

Приложение запустится в любом случае. Если датчики найти не удалось, оно
перейдёт в режим мыши: движение мыши заменяет поворот баллончика, а быстрое
потряхивание мышью взбалтывает краску — вся логика при этом работает.

Принудительный выбор источника:

```
python run.py --backend sdl      датчики через SDL
python run.py --backend hid      сырые HID-отчёты
python run.py --backend axes     гироскоп как оси джойстика
python run.py --backend mouse    мышь
```

Другие ключи: `--size 1920x1080`, `--sensitivity 700`, `--grip 270`, `--debug`.

## Управление

| Действие | Геймпад | Клавиатура |
|---|---|---|
| Подача краски | правый курок (аналоговый) | левая кнопка мыши |
| Калибровка нуля | Y | C |
| Переустановить центр | — | R |
| Палитра | A | P |
| Отмена / повтор | B / X | Z / Y |
| Размер сопла | LB / RB | `[` / `]` |
| Ячейка палитры | LB / RB при открытой палитре | 1–8 |
| Сохранить | Start | S |
| Отладочный слой | Back | F1 |
| Новый холст | — | N |
| Сменить хват | — | G |
| Выход | — | Esc |

При открытой палитре левый мини-джойстик меняет тон и насыщенность,
правый — яркость. Изменённый цвет остаётся в выбранной ячейке.

## Как это работает

Показания гироскопа и акселерометра сводятся комплементарным фильтром:
углы получаются интегрированием угловых скоростей, а крен и тангаж
подтягиваются к направлению силы тяжести. Подтягивание включается только
когда устройство почти неподвижно: иначе оно стягивало бы вертикаль обратно
к центру прямо во время ведения, и длинный мазок вверх полз бы назад.
Угол поворота вокруг вертикали акселерометром не наблюдается, поэтому его
смещение снимается калибровкой (клавиша C) и быстрым переустановлением
центра (клавиша R).

Накопленный угол удерживается в пределах холста. Без этого ограничения он
растёт неограниченно: повернув баллончик дальше края, пользователь уводит
точку за экран и вынужден отматывать ровно столько же назад, а перевалив
за половину оборота — получает перескок точки на другую сторону холста.
Ограничение накладывается на сам угол, поэтому обратное движение
возвращает курсор сразу. Пока точка стоит на краю, прицел становится
красным и краска не наносится: баллончик смотрит мимо стены. В паузах
между мазками точка медленно подтягивается к центру, съедая накопленный
дрейф, — на сам мазок это не влияет, потому что при нажатом курке возврат
отключён.

Геймпад, который держат одной рукой как баллончик, повёрнут относительно
обычного положения. Этот поворот задаётся параметром `grip_rotation` и
применяется один раз к сырым показаниям датчиков, после чего вся остальная
обработка работает так же, как при обычном хвате. По умолчанию стоит
90 градусов: поворот геймпада вправо уводит след вверх, вверх — влево,
влево — вниз, вниз — вправо. Если в руках выходит зеркально, клавиша G
перебирает четыре варианта прямо во время работы, не прерывая сеанс.

Встряхивание распознаётся по знакопеременному линейному ускорению вдоль
продольной оси устройства. Взмахом считается смена направления с амплитудой
выше 6 м/с², не чаще чем раз в 0,07 с, причём следующий взмах засчитывается
только после того, как движение затухло: без этого простой поднос баллончика
к холсту считался бы встряхиванием.

Каждый взмах поднимает уровень перемешивания на 8,5 %, то есть до ровной
подачи нужно около девяти взмахов. Перемешивание убывает само (полностью
теряется примерно за четыре минуты простоя) и дополнительно расходуется
при распылении. Чем хуже перемешана краска, тем ниже плотность и
насыщенность, тем чаще летят плотные капли и тем сильнее скачет подача;
ниже 12 % баллончик практически только плюётся.

Каждый засчитанный взмах отдаётся коротким импульсом вибромотора и стуком
шарика в динамике — звуки синтезируются при запуске, звуковых файлов в
проекте нет.

Факел рисуется гауссовым профилем, нормированным так, чтобы на границе он
обращался ровно в ноль: иначе у пятна была бы заметная круглая кайма.
Поверх профиля накладывается одна из восьми заранее просчитанных текстур
зерна — отсюда крупинчатая фактура распыла. Накопленная «влажность»
холста порождает подтёки, которые стекают вниз и собираются каплей.

## Состав

```
run.py                 запуск
probe_gamepad.py       диагностика геймпада, создаёт mapping.json
aeropaint/
  config.py            все настраиваемые параметры
  shake.py             детектор встряхивания и состояние краски
  orientation.py       комплементарный фильтр, калибровка, удаление
  spray.py             модель распыления, плевки, подтёки
  canvas.py            холст, отмена, сохранение и загрузка
  audio.py             синтез шипения и стука шарика
  ui.py                экранные элементы
  app.py               главный цикл
  inputs/              источники данных о движении
    sdl_sensor.py      SDL GameController Sensor API
    hid_raw.py         сырые HID-отчёты, формат Switch Pro
    axes.py            гироскоп как оси джойстика
    mouse.py           резервный режим мыши
    factory.py         автоподбор источника
tests/
  test_core.py         модульные тесты логики
  test_app_headless.py прогон главного цикла на заглушке pygame
  render_demo.py       наглядная отрисовка модели в PNG
```

Модули `shake`, `orientation`, `spray` и `canvas` не зависят от pygame,
поэтому проверяются без запуска графики:

```
python -m tests.test_core
python -m tests.test_app_headless
python -m tests.render_demo
```

## Если датчики не находятся

Наиболее вероятная причина — режим работы геймпада. SDL отдаёт гироскоп
контроллерам, которые публикуют его по HID; чаще всего это происходит
в режиме Nintendo Switch. Стандартный интерфейс XInput данные датчиков
не передаёт вовсе, поэтому в режиме Xbox гироскопа не будет ни в одном
приложении на Python.

Порядок действий:

1. переключить геймпад в режим Switch и снова запустить `probe_gamepad.py`;
2. если в разделе 4 протокола видны отчёты с идентификатором `0x30` —
   формат стандартный, приложение разберёт его само;
3. если формат нестандартный, в протоколе есть строка размахов по байтам:
   шесть подряд идущих активных байт обычно и есть три двухбайтовых числа.
   Их смещение вписывается в `mapping.json`, раздел `hid.custom`.

Файл `probe_report.txt` содержит полный протокол проверки.

## Настройка под себя

Все пороги собраны в `aeropaint/config.py`. Чаще всего правят:

- `ShakeConfig.accel_threshold` — если взмахи не засчитываются, порог
  занижают; если засчитываются при обычном движении, повышают;
- `ShakeConfig.mix_per_stroke` — сколько взмахов нужно до готовности;
- `OrientationConfig.px_per_rad` — чувствительность: сколько пикселей
  приходится на радиан поворота. При 700 и холсте 1600x900 рабочий сектор
  составляет около ±65 градусов по горизонтали и ±37 по вертикали; меньшее
  значение расширяет сектор, большее даёт точность в ущерб размаху;
- `OrientationConfig.auto_center_rate` — скорость самостоятельного возврата
  точки к центру в паузах, 0 отключает возврат;
- `OrientationConfig.grip_rotation` — поворот хвата, 0, 90, 180 или 270
  градусов; то же меняется клавишей G во время работы;
- `OrientationConfig.accel_tau` и `accel_still_rate` — скорость устранения
  дрейфа наклона и порог, ниже которого устройство считается неподвижным;
- `SprayConfig.hardness` и `alpha_per_stamp` — жёсткость края и укрывистость.

## Известные ограничения

Удаление от холста оценивается интегрированием продольного ускорения и
поэтому накапливает ошибку: оценка возвращается к исходной, если продольного
движения нет дольше двух секунд. Для художественного эффекта этого хватает,
для измерений — нет.

Угол поворота вокруг вертикали без магнитометра не наблюдаем, поэтому
медленный уход центра неизбежен и снимается клавишей R.

Инициализация контроллера в режиме сырых HID-отчётов реализована
минимально: отправляются команды включения датчиков и перевода в режим
полных отчётов. Полной последовательности рукопожатия, которую выполняет
SDL, здесь нет, поэтому путь через SDL предпочтителен.
