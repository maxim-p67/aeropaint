# Как запустить и проверить AeroPaint

Инструкция для Windows. Геймпад на первых шагах не нужен — сначала убеждаемся, что всё работает, и только потом подключаем контроллер.

---

## Шаг 0. Проверить, есть ли Python

Нажмите клавиши Win + R, напишите `powershell` и нажмите Enter. Откроется синее окно — это командная строка, дальше все команды набираются в ней.

Наберите и нажмите Enter:

```
py --version
```

Если ответило что-то вроде `Python 3.12.4` — всё в порядке, переходите к шагу 1.

Если открылся магазин Microsoft Store или написано, что команда не найдена, Python не установлен. Скачайте его с python.org, запустите установщик и **обязательно поставьте галочку «Add python.exe to PATH»** на первом экране установки — без неё команды работать не будут. После установки закройте окно PowerShell, откройте заново и повторите проверку.

Нужна версия 3.10 или новее.

---

## Шаг 1. Распаковать проект

Скачайте из чата файл `aeropaint.zip`. Он попадёт в папку «Загрузки».

Щёлкните по нему правой кнопкой мыши, выберите «Извлечь всё», и в появившемся окне нажмите «Извлечь». Рядом появится папка `aeropaint`, а внутри неё ещё одна папка `aeropaint` — так и должно быть.

Нужна **внешняя** папка: та, внутри которой лежат файлы `run.py`, `README.md` и `requirements.txt`. Зайдите в неё.

---

## Шаг 2. Открыть командную строку прямо в этой папке

Самый простой способ: находясь в нужной папке, щёлкните один раз по адресной строке проводника вверху (там, где написан путь), сотрите её содержимое, напишите `powershell` и нажмите Enter.

Откроется командная строка, уже находящаяся в вашей папке. Проверьте командой:

```
dir
```

В списке должны быть `run.py`, `probe_gamepad.py`, `requirements.txt`. Если их нет — вы не в той папке, вернитесь на шаг 1.

---

## Шаг 3. Установить библиотеки

```
py -m pip install -r requirements.txt
```

Установка займёт минуту-две, побегут строчки загрузки. В конце должно появиться слово `Successfully installed` со списком пакетов.

**Если увидите ошибку про pygame.** Библиотеки `pygame` и `pygame-ce` конфликтуют: обе называются в коде одинаково, и вместе они стоять не могут. Если у вас раньше стоял обычный `pygame`, сначала удалите его, потом повторите установку:

```
py -m pip uninstall pygame -y
py -m pip install -r requirements.txt
```

**Если ошибка касается `hidapi`.** Эта библиотека необязательная, без неё всё работает. Установите остальное вручную:

```
py -m pip install pygame-ce numpy Pillow
```

## Шаг 4. Проверить логику — без геймпада и без окна

Три команды, каждая проверяет свою часть. Геймпад не нужен, окно не откроется.

### 4.1. Модульные тесты

```
py -m tests.test_core
```

Пойдёт список строк, каждая начинается с `OK`. В самом конце должно быть:

```
Все проверки пройдены
```

Здесь проверяется, что детектор встряхивания считает взмахи правильно и не считает лишнего, что уровень перемешивания растёт от взмахов и убывает со временем, что плохо перемешанная краска кроет хуже, что калибровка отбрасывается при движении, что отмена и сохранение файлов работают.

### 4.2. Прогон самого приложения

```
py -m tests.test_app_headless
```

В конце должно быть:

```
Оболочка отработала без ошибок
```

Этот тест запускает главный цикл программы целиком на подставной графике: создаёт приложение, трясёт виртуальной мышью, рисует, отменяет, открывает палитру, калибрует, сохраняет файлы. Если где-то в коде опечатка, она вылезет здесь.

### 4.3. Картинки

```
py -m tests.render_demo
```

Появится папка `demo` с четырьмя файлами PNG. Откройте их двойным щелчком:

- `01_mix_levels.png` — пять одинаковых мазков при перемешивании 100, 60, 35, 18 и 6 процентов. Сверху ровная полоса, снизу почти ничего кроме капель;
- `02_distance.png` — как меняется пятно при удалении баллончика от холста;
- `03_drips.png` — подтёки от переизбытка краски;
- `04_session.png` — четыре полосы подряд, видно, как расходуется перемешивание.

Это и есть самая наглядная проверка модели.

## Шаг 5. Запустить приложение мышью

Геймпад всё ещё не нужен.

```
py run.py --backend mouse
```

Откроется окно с холстом. Курсор пропадёт — так и задумано, мышь теперь работает как баллончик.

Что делать внутри:

1. Сверху мигает надпись «ВСТРЯХНИТЕ БАЛЛОНЧИК», слева стоит указатель заполнения. **Резко потрясите мышью вправо-влево** — быстрыми короткими движениями, как трясут настоящий баллончик. Указатель начнёт заполняться, надпись погаснет примерно через девять взмахов.
2. Зажмите левую кнопку мыши и ведите — появится след краски.
3. Нажмите `F1`, чтобы включить отладочный слой справа: там видны взмахи, уровень перемешивания, частота кадров.
4. Нажмите `S` — картинка сохранится в папку `output` внутри проекта.
5. Нажмите `Esc`, чтобы выйти.

**Попробуйте наоборот:** нажмите `N` (новый холст), не трясите мышь вообще, подождите пару минут, чтобы уровень упал, и порисуйте. Краска пойдёт бледная, с перебоями и каплями. Это и есть та деталь, которую вы просили.

Остальные клавиши: `Z` отмена, `Y` повтор, `P` палитра, цифры `1`–`8` цвета, `[` и `]` размер сопла, `C` калибровка, `R` переустановить центр.

## Шаг 6. Диагностика геймпада

Теперь включите Flydigi Apex 5 и подключите его тем способом, которым собираетесь пользоваться — кабелем, через приёмник 2,4 ГГц или по Bluetooth.

```
py probe_gamepad.py
```

Скрипт идёт по пяти разделам и в двух местах просит вас покрутить и потрясти геймпад — там будет обратный отсчёт, успеете взять его в руки.

Что он делает: смотрит, видит ли геймпад pygame; ищет гироскоп среди осей джойстика; пробует получить датчики через SDL; если не вышло — читает сырые отчёты устройства; в конце записывает файл `mapping.json` с найденным способом и полный протокол в `probe_report.txt`.

**Главное, что нужно увидеть** — в разделе 3 строки:

```
гироскоп доступен: да
акселерометр доступен: да
```

и бегущие живые цифры. Если они есть, всё отлично.

**Если написано «нет».** Скорее всего, геймпад работает в режиме Xbox. Интерфейс XInput показаний гироскопа не передаёт в принципе — ни в одной программе на Python. Переключите Apex 5 в режим Nintendo Switch (обычно это сочетание кнопок на самом геймпаде, смотрите его инструкцию) и запустите диагностику ещё раз.

Если и это не помогло — пришлите мне файл `probe_report.txt`, по нему видно, что именно отдаёт устройство.

## Шаг 7. Запустить с геймпадом

```
py run.py
```

Порядок работы:

1. Положите геймпад на стол неподвижно и нажмите `C` на клавиатуре или кнопку `Y` на геймпаде. Пойдёт калибровка, она занимает пару секунд. Не трогайте геймпад в это время, иначе она отменится с сообщением об ошибке.
2. Возьмите геймпад так, как держат баллончик, и направьте на середину экрана. Нажмите `R` — это место станет центром холста.
3. Потрясите геймпад. На каждый взмах он коротко вибрирует и щёлкает, указатель слева заполняется.
4. Наводите поворотом кисти, нажимайте правый курок — чем сильнее, тем плотнее краска.
5. Движение рукой к монитору и от него меняет размер и плотность пятна.

Кнопки геймпада: `A` палитра, `B` отмена, `X` повтор, `Y` калибровка, `LB` и `RB` размер сопла, `Start` сохранить, `Back` отладочный слой.

Если след уходит в сторону от того места, куда направлен геймпад, — это накопившийся дрейф, он неизбежен. Нажмите `R`, центр переустановится, холст не пострадает.

## Если что-то пошло не так

**«py не является внутренней или внешней командой»** — Python не установлен или установлен без галочки «Add to PATH». Вернитесь к шагу 0.

**«No module named aeropaint»** — командная строка открыта не в той папке. В ней должен лежать файл `run.py`, проверьте командой `dir`.

**«No module named pygame»** — не выполнен шаг 3 либо установка прошла с ошибкой. Повторите её и посмотрите на последние строки вывода.

**Окно открылось, но всё чёрное или надписи не читаются** — не нашёлся шрифт с кириллицей. Маловероятно на Windows, но если так — напишите, поправлю список шрифтов в `aeropaint/ui.py`.

**Окно открылось, но рисовать не получается** — посмотрите на строку внизу окна: там написано, какой источник ввода выбран. Если написано «мышь», значит геймпад не подключился, вернитесь к шагу 6.

**Всё тормозит** — уменьшите холст: `py run.py --size 1280x720`.

**Слишком резко или слишком вяло водит** — поменяйте чувствительность: `py run.py --sensitivity 500` (медленнее) или `--sensitivity 1400` (быстрее).

**Взмахи не засчитываются, сколько ни тряси** — порог слишком высокий для вас. Откройте файл `aeropaint/config.py` любым текстовым редактором, найдите строку `accel_threshold: float = 6.0` и поставьте, например, `4.0`. Если наоборот, краска перемешивается сама во время рисования — поднимите до `8.0`.
